# Ethics & Content Boundaries

This system generates content for children aged 8-14 with no required human read-through
before options are shown. That makes this document load-bearing, not a formality.

**All boundaries below have been reviewed and confirmed by Wizard. This doc is fully
resolved — there are no open decisions remaining. If a future situation raises a genuinely
new boundary question not covered here, add a new section marked [NEEDS WIZARD DECISION]
rather than guessing.**

## Hard limits (no override, non-negotiable regardless of pedagogical value)
- No sexual or romantic content of any kind involving minors, explicit or implied
- No content that could function as instructions for real-world harm (weapons, dangerous
  substances, self-harm methods) even when framed as a puzzle or investigation
- No content depicting or trivializing real, named victims of real historical atrocities
- No content that asks a Riser to role-play harming another real, named person or group

## Serious themes — the line (resolved)
Your existing work already includes serious material: a resignation letter with real emotional
weight, department funding cuts, a health crisis affecting real people in a fictional city,
implied loss (Edorath's granary shortfall, workshop accident risk). This suggests you're
comfortable with real stakes and real consequence, not sanitized content.

Default, confirmed: the engine may generate concepts involving —
- loss, failure, difficult tradeoffs
- interpersonal conflict, disagreement, moral ambiguity
- fictional crisis/emergency scenarios (illness, scarcity, disaster) at a narrative level,
  not a clinical/graphic one

Requires Wizard's explicit sign-off, every instance, before being shown as a clean option —
- death of a fictional character, even non-graphic — flagged and held for review rather than
  generated freely, since this crosses from "difficult" into territory Wizard wants to see
  case-by-case
- graphic depiction of injury, death, or medical detail
- content centered on real-world tragedies, even fictionalized
- content where the "correct" answer requires the Riser to endorse a real-world political
  or religious position as fact rather than examine it

**Confirmed by Wizard. Any concept involving fictional character death is generated but
marked "requires sign-off" rather than shown as a ready option — see the Uncertainty Rule
below for how this is surfaced.**

## Cultural content (resolved)
The taxonomy includes "Cultural thinking" — perspective-taking across difference, real
cultures, real historical contexts. This is valuable and also the highest-risk category for
stereotype, flattening, or trivialization.

Default, confirmed (loosened from initial draft): the engine may reference real
cultures/history more broadly — as setting, as context, as the basis for a scenario — not
only when strictly load-bearing to a checkable task. The one rule that stays fixed: never
reduce a culture to a single trait for gameplay convenience, and never flatten a real
historical period into a stereotype for narrative ease. Real-world grounding is encouraged;
lazy or reductive use of it is not.

## Uncertainty rule
Confirmed: if the engine is uncertain whether a concept crosses a line in this document, or
if a concept involves fictional character death (see above), the behavior is: **include it
in the output anyway, visibly marked "flagged for review: [one line of reasoning]," and let
Wizard decide.** The system never silently excludes on this category of decision, and never
silently includes without the flag either — every uncertain case is surfaced, not filtered.

## Data & privacy
- No login currently exists; this reduces but does not eliminate privacy exposure
- The system must never be given, and must never generate output containing, real Risers'
  names, identifying details, performance records, or group composition
- If this changes later (e.g., logging which Riser did what), that requires a new privacy
  review before being added — not an assumption that existing rules cover it

## Change process
This is a living document. Edit any section directly. If a new boundary question comes up
that isn't covered here, add a new section and mark it [NEEDS WIZARD DECISION] so it's
visibly flagged as unresolved. The engine reads this file at generation time and at the
post-generation check step — no code change required for a boundary update to take effect.
